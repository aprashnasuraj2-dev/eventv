# EventV — Quarterly Global Event Opportunity System

Status: PLANNING ONLY (no content has been published, no ads installed).
Baseline date: 2026-11-05. Target property: aafnaipatro.com.
Owner workflow: research -> qualify -> build -> publish -> measure -> review.
This checklist does not authorize changing any live site or deploying ad code.

## 0. Non-negotiable release gate
- [ ] Confirm every ad format and placement with current Adsterra publisher rules and the site's other applicable policies.
- [ ] Never generate synthetic, forced, hidden, off-screen, duplicated, auto-refreshed, incentive-based, or bot impressions.
- [ ] No ad overlays that obstruct primary content or manipulate clicks. Respect popunder frequency caps and consent/geo rules.
- [ ] Count **actual eligible human visits**; separate Search Console SERP impressions, GA4 sessions, filled ad impressions, viewable impressions, and paid impressions.
- [ ] Every page answers a genuine question, with dated primary-source facts, named reviewer, original utility, and corrections.
- [ ] Do not mark shopping promotions, travel packages, or editorial overviews as Event structured-data objects.
- [ ] Check publishers/streaming rights before embedding footage, scores, schedules, imagery, maps or product feeds.
- [ ] Do not promise Google Discover traffic; assess it as upside only.

## 1. Quarterly discovery (repeat each Jan/Apr/Jul/Oct)
- [ ] Enumerate 15–20 events 3–18 months out; identify 1–2 near-term exceptions.
- [ ] For each event record exact date/source URL/date accessed or historic unconfirmed window/source year.
- [ ] Record primary Tier-1 countries; label Western demand share as measured vs estimated. Never equate Trends 0–100 with absolute search count.
- [ ] Identify pre-event, live, and post-event demand, including duration at >=60% of *peak*; note if multiple spikes.
- [ ] Build at least 20 candidate queries/event; manually inspect US/UK/CA/AU/EU desktop+mobile SERPs for widgets/official monopolies.
- [ ] Score demand 25%, date certainty 15%, click opportunity 25%, feasible competition 15%, monetization 20%; use 1–10 sub-scores and formula.
- [ ] Apply **separate vetoes**: YMYL without qualified reviewer, legal/licensing exposure, unsupported live coverage, no differentiator, insufficient publishing lead.
- [ ] Select max 3 concurrent major projects; log explicitly rejected high-volume events and reasons.
- [ ] Validate with GSC, Google Trends (normalized), Keyword Planner or comparable tool if connected; leave missing inputs as unknown.

## 2. Intent / cluster production
- [ ] Map pre-event: 8–12 queries grouped by planning, logistics, cost, timezone, safety, rules, how-to-watch.
- [ ] Map event-time: 8–12; mark zero-click SERP traps and viable timestamped updates.
- [ ] Map post-event: 6–10; estimate residual demand and evergreen explanation potential.
- [ ] Specify dominant emotion / urgency and expected task-oriented engagement per wave.
- [ ] Publish one canonical hub (useful first-screen answer, timestamp/timezone, table of contents, evidence/source box).
- [ ] Publish 5–8 distinct spokes, each with a unique informational job. No doorway, near-duplicate, or generic AI recaps.
- [ ] Include one defensible differentiated asset per cluster: local-time calculator, route planner, transparent price tracker, or primary-source comparison.
- [ ] Add hub↔spoke and relevant spoke↔spoke links using descriptive, natural anchors.
- [ ] Use Article/BlogPosting, BreadcrumbList, WebPage, and optional valid Event only on actual single-event attendance pages. Validate rich-result rules.
- [ ] Document title, meta description, canonical, sitemap, mobile rendering, accessibility, performance, source URLs, author/reviewer and publication/update dates.

## 3. Publication clock
- [ ] T-120 to T-90: select theme, validate sources and audience, create hub / evergreen spokes.
- [ ] T-90 to T-45: launch original tools/visuals, test mobile UX and indexing, gather baseline GSC.
- [ ] T-45 to T-14: add date-stamped spokes; establish update ownership and official fact feeds.
- [ ] T-14 to T-2: refresh confirmed schedules, tickets/availability, broadcast rights, timezones, and FAQs.
- [ ] T-1 / event day: update only on verified material changes; show UTC + local timezone and precise last-verified timestamp.
- [ ] Event +1/+3/+7/+30 days: timely recap, original analysis, evergreen redirects/internal links if warranted; preserve historical accuracy.

## 4. Impression and revenue model
- [ ] Establish per-geo **Google Search eligible query/URL impressions per day** (NOT Google Trends score), and attainable site CTR.
- [ ] Model peak-day sessions = qualified Search Console impressions/day × CTR, with separate direct/referral sessions where proven.
- [ ] Event-period viewable equivalent = peak-day sessions × equivalent peak-days × pages/session × effective ad opportunities/page × eligible fill × viewability.
- [ ] Do not model an automatic pop on every internal page view; apply actual per-session/user frequency caps, eligibility, and browser limitations.
- [ ] Treat filled, viewable-equivalent, and network-paid as different metrics; audit platform billing definitions, including CPA conversion effects.
- [ ] Keep Conservative / Realistic / Aggressive rows for each event; all inputs and revenue eCPM must be editable.
- [ ] Revenue from modeled viewable equivalents = count / 1000 × **illustrative effective viewable CPM**. Replace with network-issued paid eCPM before forecasting cash.
- [ ] Separate country, device, operating system, browser, ad format, consent status, new/returning traffic.
- [ ] Sensitivity: halve attainable CTR; halve CPM; report resulting dollar differences. Forecast is conditional, not a traffic guarantee.
- [ ] Reconcile Cloudflare edge requests/unique estimates to GA4 human sessions, GSC organic clicks, and Adsterra legitimate impressions; explain gaps before scaling.

## 5. Ad and performance quality assurance
- [ ] Verify network-approved asynchronous loader behavior without duplicate scripts or firing the same unit twice.
- [ ] Test 360/390/768/1440px layouts for real content visibility, non-obstructive unit placement, CLS and load costs.
- [ ] Confirm displayed content, not background calls, is the basis of measured exposure; log viewability method for native/display.
- [ ] Measure bounce, engaged sessions, scroll depth, pages per session and event-specific task completion.
- [ ] Check fill by geo/device/format; investigate low fill vs excluded visits vs consent/restriction vs frequency caps vs script failure.
- [ ] Pause any placement that degrades user navigation, accessibility, or publisher compliance.
- [ ] Respect GDPR/UK GDPR/ePrivacy/cookie requirements where relevant; review with appropriate counsel as needed.

## 6. Reporting and decision gates
- [ ] Weekly: GSC query/page/country CTR and positions, GA4 session quality, indexation, updates/corrections, Adsterra stats.
- [ ] Daily during event: visit-to-impression funnel, verified source changes, errors and ad experience.
- [ ] Postmortem +7: actuals vs scenario by event, revenue per 1,000 legitimate sessions, highest converting information gaps.
- [ ] Postmortem +30: retained queries, discover visibility only if observed, evergreen decay, content production cost.
- [ ] Record gross ad revenue, writing/engineering/update costs and gross contribution, not revenue alone.
- [ ] Decision rule: expand a cluster only if validated Tier-1 organic clicks grow, quality remains healthy, unit economics justify updates, and no policy concerns appear.
- [ ] Move each event to one of RESEARCH / APPROVED / PUBLISHED / LIVE / RETROSPECTIVE / STOP.
